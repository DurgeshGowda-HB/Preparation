## Amazon Elastic Compute Cloud (Amazon EC2)

Amazon EC2 (Elastic Compute Cloud) is a service that provides **virtual servers** in the cloud to run applications.

<h3>Why Do We Need EC2?</h3>

Traditionally, running an application requires:

- Buying a Physical Server
- Installing an Operating System
- Maintaining Hardware
- Upgrading Resources

With EC2, AWS provides virtual servers on demand.

<h2>What is Amazon EC2?</h2>

> **Definition:** Amazon EC2 is a cloud computing service that provides resizable virtual servers (instances) to run applications.

Simply:

> **EC2 = Rent a Virtual Computer in the Cloud.**

<h3>How EC2 Works</h3>

```text
User
 │
 ▼
Launch EC2 Instance
 │
 ▼
Install Application
 │
 ▼
Users Access Application
```

<h2>Key Components</h2>

### EC2 Instance

> A virtual machine running in AWS.

### AMI (Amazon Machine Image)

> A template used to launch an EC2 instance.

It contains:

- Operating System
- Software
- Configuration

### Instance Type

> Defines the CPU, RAM, Storage, and Network capacity of an EC2 instance.

Example:

- t2.micro
- t3.micro
- t3.small

### Key Pair

> Used to securely connect to an EC2 instance using SSH.

### Security Group

> A virtual firewall that controls inbound and outbound traffic defines who are allowed to access it

### Elastic IP

> A static public IP address that can be associated with an EC2 instance.

<h3>Common Use Cases</h3>

- Web Hosting
- Running Backend Applications
- Hosting APIs
- Development & Testing
- Batch Processing
- Game Servers

<h3>Benefits of Amazon EC2</h3>

- On-demand Virtual Servers
- Easy to Scale
- Pay-as-you-go
- Secure
- Highly Available
- Multiple Operating Systems Supported

<h3>EC2 vs Physical Server</h3>

| Feature | Physical Server | Amazon EC2 |
|---------|-----------------|------------|
| Setup Time | Days or Weeks | Minutes |
| Initial Cost | High | No Upfront Cost |
| Scalability | Difficult | Easy |
| Maintenance | Self Managed | AWS Manages Hardware |
| Pricing | Buy Hardware | Pay-as-you-go |

<h2>Key Takeaways</h2>

- EC2 provides **virtual servers** in the cloud.
- An **EC2 Instance** is a virtual machine.
- **AMI** is used to launch EC2 instances.
- **Instance Type** determines CPU, RAM, and other resources.
- **Security Groups** protect EC2 instances.
- **Key Pairs** are used for secure login.
- **Elastic IP** provides a static public IP address.
- EC2 follows a **Pay-as-you-go** pricing model.

## EC2 — Allow Friend to Access Your Instance

> **Security Group = controls which IPs can reach EC2.**
> **SSH key = controls who can log in.**

## Add Friend's IP

Go to:

**EC2 → Security Groups → your Security Group → Inbound rules → Edit inbound rules**

Add:

```text
Type: SSH
Port: 22
Source: Custom
IPv4: FRIEND_PUBLIC_IP/32
```

Example:

```text
SSH | TCP | 22 | 122.172.82.76/32
```

Keep your own rule:

```text
SSH | TCP | 22 | YOUR_IP/32
```

So the Security Group can have:

```text
SSH | TCP | 22 | YOUR_IP/32
SSH | TCP | 22 | FRIEND_IP/32
```

> Use the friend's **public IPv4**, not `192.168.x.x`.

## Friend Creates His Own SSH Key

On your friend's **Windows PowerShell**:

```powershell
ssh-keygen -t ed25519
```

Press **Enter** to use the default location:

```text
C:\Users\Friend\.ssh\id_ed25519
```

The two important files are:

```text
id_ed25519      → 🔒 Private key
id_ed25519.pub  → 🔓 Public key
```

### Get the Public Key

```powershell
Get-Content "$env:USERPROFILE\.ssh\id_ed25519.pub"
```

It looks like:

```text
ssh-ed25519 AAAAC3... friend@computer
```

Friend sends **only this public-key line** to you.

 Never send:

```text
id_ed25519
```

## Add Friend's Key to Your EC2

On **your computer**, connect using your own `.pem`:

```bash
ssh -i ".\aws-learning.pem" ec2-user@YOUR-PUBLIC-DNS
```

Inside EC2:

```bash
nano ~/.ssh/authorized_keys
```

You'll already have your public key.

Go to a **new line** and paste your friend's:

```text
ssh-ed25519 AAAAC3... friend@computer
```

So it becomes:

```text
YOUR_PUBLIC_KEY
FRIEND_PUBLIC_KEY
```

Save:

```text
Ctrl + O
Enter
Ctrl + X
```

Then:

```bash
chmod 600 ~/.ssh/authorized_keys
```

## Friend Connects

On **your friend's computer**, he does **not** need your `.pem`.

He uses his own private key:

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519" ec2-user@YOUR-PUBLIC-DNS
```

Example:

```powershell
ssh -i "$env:USERPROFILE\.ssh\id_ed25519" ec2-user@ec2-18-61-75-31.ap-south-2.compute.amazonaws.com
```

##  Complete Flow

```text
FRIEND'S PC
    │
    ├── id_ed25519 🔒
    │
    └── id_ed25519.pub 🔓
              │
              │ Send PUBLIC key
              ↓
       YOUR EC2 INSTANCE
              │
              └── ~/.ssh/authorized_keys
                    │
                    ├── Your public key
                    │
                    └── Friend's public key
```

And separately:

```text
Security Group
    │
    ├── SSH : 22 : YOUR_PUBLIC_IP/32
    │
    └── SSH : 22 : FRIEND_PUBLIC_IP/32
```

## Remember

> **Security Group controls whether the friend's computer can reach SSH.**

> **`authorized_keys` controls whether the friend is allowed to log in.**

> **Don't create a `.pem` and send it to your friend.**

> **Each person should have their own private/public key pair.**

> **Private key stays with the person. Public key can be added to `authorized_keys`.**

## Amazon CloudWatch

Amazon CloudWatch is an AWS **monitoring and observability service** used to monitor AWS resources, applications, and infrastructure.

<h3>Why Do We Need CloudWatch?</h3>

Suppose our application is running on EC2.

We need to know:

- Is the server running?
- How much CPU is being used?
- Are there errors?
- Is the application performing properly?

CloudWatch helps us **monitor and detect problems**.

```text
EC2 / Application
       │
       ▼
  CloudWatch
       │
 ┌─────┼─────┐
 ▼     ▼     ▼
Metrics Logs Alarms
```

<h2>What is Amazon CloudWatch?</h2>

> **Definition : Amazon CloudWatch is a monitoring and observability service that collects metrics, logs, and events from AWS resources and applications.**

Simply:

> **CloudWatch = Monitor AWS resources and detect problems.**

<h3>Key Components</h3>

### Metrics

> Metrics are numerical measurements that show the performance or health of a resource.

Examples:

- CPU Utilization
- Network Traffic
- Request Count
- Error Count

Example:

```text
EC2 CPU Usage
     │
     ▼
CloudWatch Metric
     │
     ▼
CPU = 85%
```

### Logs

> Logs contain records of events and activities generated by applications and AWS resources.

Example:

```text
Spring Boot Application
        │
        ▼
      Logs
        │
        ▼
   CloudWatch Logs
```

Useful for finding:

- Application errors
- Exceptions
- Failed requests
- Debugging information

### Alarms

> An alarm monitors a metric and performs an action when a defined threshold is reached.

Example:

```text
EC2 CPU Usage
      │
      ▼
   CloudWatch
      │
 CPU > 80% ?
      │
     YES
      │
      ▼
  CloudWatch Alarm
      │
      ▼
   SNS Notification
      │
      ▼
   Email / SMS
```

<h3>Common Use Cases</h3>

- Monitor EC2 instances
- Monitor application performance
- Collect application logs
- Create alerts
- Detect failures
- Track AWS resource usage

<h3>CloudWatch vs CloudTrail</h3>

| CloudWatch | CloudTrail |
|------------|------------|
| Monitoring & Observability | Auditing & API Activity |
| Metrics, Logs, Alarms | Records API calls |
| "How is my system performing?" | "Who performed this action?" |
| Detect performance problems | Track user/API activity |

<h3>Example</h3>

Suppose your Spring Boot application is running on EC2.

```text
                 EC2
                  │
          ┌───────┴───────┐
          ▼               ▼
       Metrics           Logs
          │               │
          └───────┬───────┘
                  ▼
             CloudWatch
                  │
                  ▼
                Alarm
                  │
                  ▼
                 SNS
                  │
                  ▼
             Email / SMS
```

If CPU usage becomes too high, CloudWatch can trigger an alarm and notify the administrator.

<h2>Key Takeaways</h2>

- **CloudWatch = Monitoring and Observability.**
- **Metrics** show resource performance.
- **Logs** help troubleshoot applications.
- **Alarms** notify us when a metric crosses a threshold.
- CloudWatch can monitor AWS resources and applications.
- **CloudWatch → "How is my system performing?"**
- **CloudTrail → "Who did what in my AWS account?"**
